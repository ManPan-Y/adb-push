# ADB 无线推送工具（Windows）

<div align="center">

**一个窗口 / 一条命令，把本地文件或文件夹无线推送到安卓设备。**

裸 `adb push` 传到一半断线就前功尽弃、没有任何校验、也不能反向拉取——本工具一次性补齐：
**断点续传 · 大小+哈希双校验 · 差异同步 · 双向互传 · 并行加速**。

纯 Python 标准库（零第三方依赖）+ 系统 `adb`，双击即用，无需配置任何环境。

## 为什么用它？（对比裸 `adb push`）

| 痛点 | 裸 `adb push` | 本工具 |
| --- | --- | --- |
| 大文件传到一半断线 | 设备端不留残留，**只能从头再传** | **断点续传**（push / pull 均支持），从断点继续 |
| 传完不知道对不对 | 没有任何校验 | **大小 + 哈希双校验**，不一致明确报错并列出明细 |
| 重复同步一堆文件 | 要么全量覆盖、要么手动逐个挑 | **差异同步**：只传「缺失」或「内容不一致」的文件 |
| 只能本地 → 设备 | 无 pull 能力 | **双向**：`push`（本地→设备）/ `pull`（设备→本地） |
| 上千个小文件很慢 | 单条流 + 每文件进程开销 | **文件级 + 分块级并行**，实测最高 **7.2×** |
| 必须有线连接 | 需要 USB | **无线调试**：mDNS 自动发现、配对码、断线自动重连 |
| 只能敲命令行 | 无界面 | **Tkinter 图形界面**，设备/方向/进度全过程可视化 |

**实测性能（真机 WiFi，仅供参考）**

| 场景 | 串行 | 并行 |
| --- | --- | --- |
| 120 个 64KB 小文件 | 10.8s（11 文件/s） | 1.5s @ `-j16`（80 文件/s，**7.2×**） |
| 4 个 20MB 大文件 | 34.8 MB/s | 81.5 MB/s @ `-j4`（**2.3×**） |
| 单个 60MB 大文件 | 13.4 MB/s | 27.9 MB/s @ `-j4`（**2.1×**） |

## 二、核心能力（双向 / 双校验 / 续传 / 差异同步）

| 能力 | 说明 | 开启方式 |
| --- | --- | --- |
| **文件夹互传** | 支持 `push`（本地→设备）与 `pull`（设备→本地），递归整个文件夹；目标相对路径 = `顶层名/子路径`，**完整保留相对目录结构** | `--direction pull` 或 `--pull` |
| **双校验** | 传输后同时比对**大小**与**哈希**（设备端 `md5sum`/`sha256sum`/`sha1sum` 自动探测）。任一项不符即判失败并列出明细 | `--verify hash`（默认） |
| **随时中断 + 续传** | 取消标志在**每个分片/每次读取**之间检查，大文件也能即时中断；已传部分保留，下次运行**自动续传**。push 与 pull 都支持，且续传后会做哈希校验 | 默认开启；`--no-resume` 关闭 |
| **按需差异传输** | `diff` 模式只传「目标端缺失」或「哈希不一致」的文件：大小不同直接判不一致，**大小相同再比哈希**（因此同大小不同内容也能识别）。两侧哈希均按 `size+mtime` 缓存；远端未命中时走**整目录一次批量 md5sum**，本地则**并行**计算，避免 O(文件数) 次 adb 往返 | `--mode diff`（默认） |
| **并行加速（两级）** | 多文件时按**文件级**并行（线程池）；单个大文件时按**分块级**并行（push 走分片并行上传+设备端按序合并，pull 走 `dd` 范围读取+本地拼接）。两级并发相乘不超过 `--jobs` | `--jobs 4`（默认） |
| **实时速率 + 预计时长** | 进度条与 GUI 都显示当前速度（滑动窗口速率，非平均值，续传时不会虚高）与**预计剩余时长（ETA）** | 默认 |
| **保留相对目录结构** | 推送/拉取均按源端顶层名建立目标子目录，逐级 `mkdir`；中文与空格路径全程安全 | 默认 |

### 续传是怎么做到的（实现要点）

- **`adb push` 本身不能续传**：实测中断后设备端**不留任何残留**（内部是临时文件+改名），所以不能靠它断点续传。
- **push 续传** = 本地按 `--chunk-size` 分片 → 每片 `adb push` 成独立文件 `<目标目录>/.adbp/<key>/NNNNN.part` → 全部就绪后**一次 `cat` 合并** → `mv` 成最终文件。续传以**分片**为单位：大小与期望一致的分片直接跳过。
  - 「每分片独立文件 + 一次合并」同时服务**串行**与**并行**，两者共用同一套暂存布局，所以中途改 `--jobs` 也能继续续传。
  - 相比「逐片追加到同一个 part」，合并只需 1 次 `adb shell`，而追加需要与分片数相同的次数（大文件动辄几百次）。
  - 文件不超过一个分片时走快路径：**直接推最终路径**（此时续传粒度本就是整个文件，走暂存没有收益）。
- **pull 续传** = `adb exec-out tail -c +N` 从精确字节偏移拉取并追加到本地 `.part`，中断后按 `.part` 大小续传；大文件则用 `dd skip/count` 分块并行下载后本地拼接。若检测到设备端错误文本混入数据流，会立即丢弃该 `.part`，避免拼出坏文件。
- 设备端暂存目录 `目标目录/.adbp/` 在传输完成后自动清理；同时会**一次性清理旧版布局残留**（`<key>.part`/`<key>.chunk`）。
  - ⚠️ 因为暂存格式变了，**升级后正在传输中的文件会从头重传**（已完成的文件不受影响，会被差异同步跳过）。
  - ⚠️ 暂存目录按 `文件路径 + 大小 + 分片大小` 区分，因此**中途改动 `--chunk-size` 会让该文件从头重传**（这是刻意的：分片大小一变，旧分片的字节偏移就全变了，沿用会拼出错误内容）。
- **合并前的原子校验**：分片全部就绪后先合并到暂存文件，**在设备端确认大小完全正确后才改名成最终文件**；大小不符则只留下暂存文件、目标文件保持不变，重跑会自动重传缺失分片。

### 并行是怎么分配的（避免二次并发把 adb 打爆）

```
file_workers  = min(jobs, 待传文件数)
chunk_workers = max(1, jobs // file_workers)
```

- **120 个小文件 + `-j 4`** → 4 个文件并行，单文件内不再分片（`4 × 1`）。
- **1 个 500MB 大文件 + `-j 8`** → 单文件独占 8 路并行分片（`1 × 8`）。
- 这样 **任意时刻的并发 adb 连接数都不超过 `jobs`**，不会因为两级并行相乘把 adb server 打死。
- 只有文件大小 ≥ `--parallel-threshold`（默认 64MB）时才启用分块并行——小文件分片反而被进程开销拖慢。

### 实测性能（真机 WiFi，仅供参考）

| 场景 | 串行 | 并行 |
| --- | --- | --- |
| 120 个 64KB 小文件 | 10.8s（11 文件/s） | 1.5s @ `-j16`（80 文件/s，**7.2×**） |
| 4 个 20MB 大文件 | 34.8 MB/s | 81.5 MB/s @ `-j4`（**2.3×**） |
| 单个 60MB 大文件 | 13.4 MB/s | 27.9 MB/s @ `-j4`（**2.1×**） |

> 说明：并行提速的原理是「adb 单条流跑不满 WiFi 带宽 / 每文件都有进程启动开销」。
> 实测写入 `/sdcard`（FUSE）与 `/data/local/tmp`（原生分区）速率几乎一致，
> 说明瓶颈在传输通道而非文件系统；**root 不会让传输变快**。

## 三、CLI 参数

```
# 推送（本地 → 设备）：差异同步 + 双校验 + 断点续传，全部为默认行为
python adb_push.py --source "D:\我的文件" --target "/sdcard/Download/我的文件"

# 拉取（设备 → 本地）
python adb_push.py --pull --source "/sdcard/DCIM/Camera" --target "D:\照片备份"

# 先比对不传输
python adb_push.py --source "D:\我的文件" --target "/sdcard/Download" --dry-run
```

| 参数 | 说明 |
| --- | --- |
| `--source, -s` | 源路径：push 时为本地路径，pull 时为设备路径 |
| `--target, -t` | 目标路径：push 时为设备目录，pull 时为本地目录 |
| `--direction` | `push`（默认，本地→设备） \| `pull`（设备→本地） |
| `--pull` | 等价于 `--direction pull` |
| `--mode` | `diff`（默认，缺失或哈希不一致才传） \| `overwrite`（总是传） \| `skip-existing`（目标端已存在则跳过） \| `newer`（源修改时间较新才传） |
| `--verify` | `hash`（默认，**大小 + 哈希双校验**） \| `size`（仅大小） \| `none`；不带值等价于 `hash` |
| `--hash-algo` | `md5` \| `sha256` \| `sha1`，默认自动探测设备支持（通常 md5） |
| `--no-resume` | 关闭断点续传 |
| `--jobs, -j` | 并发上限，默认 4（`1` = 完全关闭并行）；多文件按文件并行，单大文件按分片并行 |
| `--parallel-threshold` | 单文件达到该大小（MB，默认 64）才启用分块级并行 |
| `--chunk-size` | 分片大小（MB，默认 8），决定续传粒度与分块并行粒度 |
| `--no-cache` | 不使用远端哈希清单缓存（每次重新计算） |
| `--dry-run` | 只打印将要执行的操作，不做任何传输 |
| `--newer-only` | 等价于 `--mode newer` |
| `--serial` | 指定设备序列号（多设备时使用） |
| `--address, -a` | 无线设备地址 `IP:端口` |
| `--connect-address` | 配对后用于 `adb connect` 的 `IP:端口` |
| `--pair-code` | 配对码（不填则交互输入） |
| `--port` | tcpip/connect 端口，默认 `5555` |
| `--device-ip` | 手动指定设备 IP |
| `--adb` | 指定 adb 可执行文件路径 |
| `--devices` | 列出当前设备 |
| `--auto` | 自动发现并连接设备（已有 USB/无线设备则复用，否则 mDNS 发现后自动连接） |
| `--discover` | mDNS 发现同网段开启无线调试的设备 |
| `--pair` | 进入 Android 11+ 无线配对流程 |
| `--connect` | 仅连接设备，不推送（未给 `--address` 时自动走 mDNS） |
| `--to-wireless` | 由 USB 切换为无线调试（`adb tcpip` + `adb connect`） |
| `--config` | 配置文件路径，默认同目录 `config.json` |
| `--batch` | 按配置文件 `jobs` 批量推送 |
| `--save-config` | 将 `--address` / `--target` 写入配置 |
| `--quiet` | 精简输出（不显示进度条） |

## 四、配对流程图（文字版）

### A. 传统方式（Android 10 及以下 / 想固定端口）

```
① 手机：设置 → 关于手机 → 连点「版本号」7 次 → 打开开发者选项
② 手机：开发者选项 → 打开「USB 调试」
③ 数据线连接电脑，手机弹出授权 → 勾选「始终允许」→ 允许
④ 电脑执行：python adb_push.py --to-wireless --port 5555
        ├─ 自动读取设备 IP（ip route / ip addr / ifconfig）
        ├─ adb tcpip 5555      （adbd 切换到 TCP 模式）
        └─ adb connect <IP>:5555 → 等待 device 状态
⑤ 拔掉数据线，直接：python adb_push.py --source ... --target ...
```

### B. Android 11+ 无线调试（配对码）

```
① 手机：设置 → 开发者选项 → 打开「无线调试」
② 手机：无线调试 → 「使用配对码配对设备」
        └─ 显示：IP 地址与端口(配对端口) + 6 位配对码
③ 电脑：python adb_push.py --pair
        ├─ adb pair  <IP>:<配对端口> <配对码>      （仅首次）
        └─ adb connect <IP>:<连接端口>            （无线调试主页显示的端口）
④ 之后：直接 python adb_push.py --source ... --target ...
        （连接端口每次开启无线调试可能变化，可用 --discover 自动发现）
```

## 五、ADB（Platform Tools）安装与配置

1. 下载：<https://developer.android.com/tools/releases/platform-tools> → 解压到例如 `C:\platform-tools`。
2. 配置（任选其一，本工具会自动按顺序查找）：
   - **加 PATH**：`此电脑 → 属性 → 高级系统设置 → 环境变量 → Path → 新增 C:\platform-tools`
   - **设 ADB_PATH**：新建环境变量 `ADB_PATH = C:\platform-tools\adb.exe`
   - **放同级目录**：把 `platform-tools` 文件夹放到本工具目录或其父目录下
   - **命令行指定**：`python adb_push.py --adb "C:\platform-tools\adb.exe" ...`
3. 验证：`adb version`

## 六、安装与运行

1. 安装 Python 3.10+（3.12 推荐），安装时勾选 **Add Python to PATH**。
2. 双击 `启动GUI.bat` 打开图形界面；或 `启动命令行.bat` / 直接用命令行。
3. 无需 `pip install`（仅标准库）。

### 图形界面（全过程可视化）

- **环境**：显示/手动选择 adb 路径
- **设备连接**：自动连接、刷新设备、USB 转无线、无线配对、连接地址、mDNS 发现、断开
  - 启动后会自动搜索并连接设备（USB 或同 WiFi 的无线调试），无需手动填 IP
- **传输配置**：方向（推送/拉取）、源路径、目标路径、已存在处理（差异同步/覆盖/跳过/仅较新）、双校验方式（大小+哈希/仅大小/不校验）、断点续传开关、**并发数**、试运行
- **路径选择随方向自动切换**（避免把本地路径当成设备路径）：
  - `推送 本地→设备`：源用【本地文件 / 本地文件夹】；目标用【设备目录…】打开**手机目录浏览器**
  - `拉取 设备→本地`：源用【设备文件 / 设备目录】打开**手机目录浏览器**；目标用【本地目录…】
  - 设备浏览器支持双击进入、上级、转到、快捷入口（/sdcard、Download、DCIM、Documents、Pictures）；不选任何项点「确定」= 选用当前目录
  - 方向与路径类型不匹配时（例如拉取却填了 `C:\...`），开始前会直接提示「路径不对」，而不是抛出难懂的报错
- **进度显示分为三个独立字段**（互不干扰，便于一眼看清各维度）：
  - `进度`：百分比进度条 + 当前文件计数 + 已传/总字节（续传也不会溢出）
  - `速度`：实时速率 + 预计剩余时长（ETA）
  - `状态`：当前正在做的事（比对中 / 传输某个文件 / 校验 / 结束汇总），跟随最新日志自动刷新
- **日志**：带颜色的实时日志（成功/警告/失败）
- 断线自动重连、传输结束弹出汇总

## 七、配置文件（config.json）

复制 `config.example.json` 为 `config.json`：

```json
{
  "devices": [{ "address": "192.168.1.147:5555" }],
  "targets": ["/sdcard/Download/", "/sdcard/PC_GAME/"],
  "jobs": [
    { "source": "D:/我的文件", "target": "/sdcard/Download/我的文件",
      "direction": "push", "mode": "diff", "verify": "hash" },
    { "source": "/sdcard/DCIM/Camera", "target": "D:/照片备份",
      "direction": "pull", "mode": "diff", "verify": "hash" }
  ]
}
```

批量执行：

```bash
python adb_push.py --batch --config config.json
```

## 八、行为细节与实现要点

1. **中文与空格**：所有命令通过 `subprocess` 的**参数列表**传递，不做字符串拼接；经 `adb shell` 执行的远端路径用单引号转义（`_sh_quote`）。
2. **相对目录结构**：`os.walk` / `find` 递归枚举，目标相对路径 = `顶层名/子路径`（与 `adb push 目录 /目标/` 语义一致），推送前对每个子目录 `mkdir -p`。
   - 远端枚举一律用 `find -H`：`/sdcard` 本身是**符号链接**，不加 `-H` 时 toybox 的 find 不会进入它，会被误判成空目录（拉取 `/sdcard` 会直接报「源为空或不可读」）。
3. **双向**：`--direction push/pull`。拉取端用 `adb exec-out`（无 CRLF 转换，二进制安全）。
4. **差异同步**：`--mode diff` 只传「目标端缺失」或「哈希不一致」的文件；大小不同直接判定不一致，大小相同再比哈希。
   - **比对代价被刻意压到最低**（否则上千文件会卡住十几分钟）：
     - 远端一侧：先查 `size+mtime` 缓存；未命中到阈值时改为**整目录一次 `find -exec md5sum +`（仅 1 次 adb 调用）**并**流式汇报进度**，只有零星未命中才逐文件查询；
     - 本地一侧：**多线程并行**计算，同样带 `size+mtime` 缓存；
     - 两侧缓存分别落在 `.adbp_cache/remote__*.json` 与 `local__*.json`，文件没变时重复同步**完全不读盘、不查哈希**。
   - 实测（500 个文件、全部同大小需比对）：**18.3s → 1.03s（冷缓存）/ 0.55s（热缓存）**。
5. **双校验**：`--verify hash` 传输后同时比对**大小**与**哈希**（设备端 `md5sum`/`sha256sum`/`sha1sum`，自动探测），任一项不符即标记失败。
6. **断点续传（push）**：`adb push` 中断后设备端不留残留，**无法直接续传**，因此改为「本地分片 → 每片推成独立文件 `.adbp/<key>/NNNNN.part` → 一次 `cat` 合并 → `mv` 到最终位置」。续传判定以**分片**为单位（大小一致即跳过），串行与并行共用同一套布局。
7. **断点续传（pull）**：`adb exec-out tail -c +N` 从精确字节偏移拉取并追加到本地 `.part`，中断后按 `.part` 大小续传。若检测到错误文本混入数据流会立即丢弃该 `.part`，避免拼出坏文件。
8. **随时中断**：取消标志在**每个分片/每次读取**之间检查，大文件也能即时中断；已传部分保留，下次自动续传。
9. **断线重连**：识别 `device offline / not found / connection reset` 等，自动 `adb connect` 重连后重试（默认重试 2 次）。
10. **进度**：已完成文件字节数 + 当前文件已传字节数，因此续传时进度既不倒退也不超过 100%。
11. **并行**：文件级用 `ThreadPoolExecutor`；分块级 push 为「每分片独立文件 + 设备端按序 `cat` 合并」，pull 为「`exec-out sh -c "dd … skip/count"` 范围读取 + 本地拼接」。并发上限统一由 `jobs` 约束。
12. **目录创建去重**：同一远端目录只 `mkdir` 一次（`_DirRegistry`），否则大量小文件会被逐文件的 mkdir 往返拖慢数倍。
13. **速度与 ETA**：`SpeedMeter` 滑动窗口（默认 4s）计算瞬时速率，避免用累计平均值导致「续传时速度虚高」；预计剩余时长 = 剩余字节 ÷ 该速率。
14. **GUI 线程边界**：Tkinter 变量不是线程安全的，因此后台线程一律只使用
    「主线程快照 `_snapshot()`」或纯文本镜像 `serial_live`；后台需要弹窗时通过
    `_ask_main()` 回到 UI 线程执行，绝不跨线程读写控件。
15. **路径规范**：本地用 `os.path`，远端统一正斜杠（`posixpath.join`）。
16. **权限**：推送到 `/sdcard` 一般无需 root；推送 `/data` 等需 root，失败会给出明确提示。**root 与传输速度无关**（实测 `/data/local/tmp` 与 `/sdcard` 速率一致）。

## 九、常见错误与解决办法

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 双击 bat 弹出 `Python was not found ... Microsoft Store` | 只装了应用商店的 python 占位别名，并非真 Python | 安装真 Python 3.10+（勾选 Add to PATH）；或在「设置→应用→高级应用设置→应用执行别名」关闭 python.exe/python3.exe |
| bat 窗口一闪而过 | 同上，脚本未检测到可用 Python | 启动脚本现已自动识别并给出明确提示 |
| 拉取时报 `源为空或不可读` | 源路径填成了本地路径（拉取要求设备路径，须以 `/` 开头） | 用【设备文件 / 设备目录】按钮选；新版会直接提示「路径不对」 |
| 拉取 `/sdcard` 看不到文件 | `/sdcard` 本身是符号链接，旧版 `find` 未跟随 | 已修复：远端枚举统一加 `-H` 跟随命令行符号链接 |
| `未找到 adb 可执行文件` | 未安装/未配置 PATH | 见「五、ADB 安装与配置」 |
| `未检测到可用设备` | 未授权 / 未连接 | 运行 `--auto` 自动连接；或手机确认授权弹窗后 `--to-wireless` / `--pair` |
| `unauthorized` | 未点「允许调试」 | 手机上重新允许；可 `adb kill-server` 后重连 |
| `device offline` | 无线不稳 / adbd 重启中 | 工具会自动重连；仍失败则 `--connect` 重连 |
| `adb pair` 失败 | 配对码过期 / 端口填错 | 重新打开配对弹窗、核对端口 |
| `cannot connect to <IP>:5555` | 不同网段 / 防火墙 | 手机与电脑同一 WiFi；放行 5555；关闭 VPN |
| `connect failed: ECONNREFUSED` | 未先 `adb tcpip` | 先 USB 执行 `--to-wireless` |
| `Permission denied` | 目标目录需 root | 改推 `/sdcard/...` 或使用 root 设备 |
| `[校验] 不一致`（哈希不同） | 传输中断 / 磁盘满 / 设备端被改动 | 重跑（会自动按哈希差异重传该文件） |
| 设备端出现 `.adbp/` 目录或 `*.part` | 传输被中断，暂存保留以便续传 | 正常现象；重跑会自动续传并在完成后清理 |
| 中文名乱码 | 终端编码 | 已用 UTF-8 解码；`chcp 65001` 后重试 |
